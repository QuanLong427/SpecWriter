# v0.8：阶段 A 的实现与验证范围

本轮按 [优化方案](long-form-optimization-plan.md) 实施 A 阶段，把任务约定、章纲、记忆、写作授权和恢复入口接在一起。Codex 继续负责创作、提取和语义审阅；CLI 校验边界，不独立生成正文。

## 当前能做什么

| 环节 | 生产者 | 使用者和边界 |
| --- | --- | --- |
| 采用约定 | 作者选择，Codex 完善四份 Spec，contract adopt | SQLite 保存不可随草稿修改的快照；prepare 按章节选版本；新采用使未完成上下文过期 |
| 写作范围 | 作者指令，work authorize | prepare/commit 检查章节及暂停；draft 不能接纳，auto 才能接纳；既有授权不重复确认 |
| 结构化章纲 | intent seed，Codex 填 JSON，intent save | schema 和正式记忆检查依赖；生成可读 intent.md，绑定 context/delta/review |
| 必选记忆 | 人物/POV 及显式状态、余额、事件、伏笔依赖 | 关键记录与上章结尾受保护；不够预算拒绝，不静默删；缺登记认知提示核对 |
| 写作与审阅 | Codex 用 context 写草稿，提取和审阅 | verify 检查声明及 intent_checks 的引用、版本与结论记录；语义判断仍需实际审阅 |
| 恢复 | resume 读取当前工作包、约定、政策及文件 | 不调用模型；区分缺章纲、刷新、写作、提取、审阅、待接纳、暂停、范围完成等状态 |
| 备份 | version save 或自动检查点 | 包含约定和政策；单独暂停/授权变化也检测待备份；恢复到新目录保留暂停 |
| 用户入口 | 新 $specwriter＋已有七个专项 Skill | 自然语言开始/继续/审阅；阅读器和导出保持简洁，不要求作者操作内部 JSON |

工作流见 [workflow.md](../packages/specwriter/assets/workflow.md)。新书默认 structured，旧配置保持原流程，采用 contract 才启用；历史 delta/review 不改写。init 升级保留用户改动过的 Skill，安装指南同步到源码和包。

## 回归验证

`npm.cmd test`：96 项全部通过。验证原有记忆、GraphRAG 适配、阅读器、Git 备份与用量边界，并加入 v08 用例：

- 缺约定、缺授权、空/未保存章纲拒绝准备；引用依赖缺失和必选预算不足在模型调用前失败。
- 草稿可以审阅，draft 不可接纳；作者接纳后只改变 auto 政策，不强迫重做有效审阅。
- 暂停阻止 prepare/commit，保留 verify；建库期间暂停阻止下一次查询与上下文发布。
- 约定草稿编辑不改变已采用版本，采用新版本使未完成上下文过期；选中的未来计划不进入正式记忆。
- POV 状态、旧事件、伏笔、余额和上章结尾保留；章纲/正文变化导致提取和审阅过期。
- intent_checks 缺项、无正文引用、重复/过期项均拒绝；新人物必须有正式登场记录。
- 旧章修订后顺序恢复 stale 后文，当前上下文不混入未来正文。
- 政策变更可备份与恢复；旧数据库迁移、用户修改过的入口 Skill 保留、新 CLI 指令可调用。

这些测试是手工构造的确定性夹具，验证协议，不能算语义准确率。八份 Skill 使用 skill-creator 的 quick_validate 验证格式；构建和安装包检查覆盖新增入口与 schema。specwriter-0.8.0.tgz 在独立目录安装后成功创建新书并通过本地启动器执行 resume，默认 structured、8 个 Skills。这里的独立安装复用本机 Node/npm，不等于全新机器验收。

## 原创短篇流程演练

`npm.cmd run demo:journey` 在一个新目录建立《渡口的灯》，显式使用 local 后端，写入本次 Codex 编写的三章原创短篇及逐章具体提取、审阅说明。

实际结果：3 章，1927 个 JavaScript UTF-16 字符（包括标题、标点与空白），模型调用 0。第一章先到 await-acceptance，后两章按演练预先指定的 auto 范围接纳；新进程恢复暂停；三章连续有效，doctor healthy=true；TXT、Markdown、HTML 导出成功，范围完成后归档。

检查的故事连续性包括：阿宁位置从渡口到渡船再到对岸石阶；铜钱八减二剩六且第三章不再支出；白伯解释先记作角色听到的说法，后经问答动作验证缺口信号；字条作者和姐姐去向保持未确立，旧伏笔兑现与新线索分别登记。

可复现来源为 [正文及章内审阅](../packages/specwriter/examples/author-journey-data.mjs) 和 [演练脚本](../packages/specwriter/examples/author-journey.mjs)。指定其他新目录可重跑：`node packages/specwriter/examples/author-journey.mjs E:/experiments/author-journey-02`。已有目录会拒绝覆盖。数据是固定样例，重跑不生成新的小说，也不独立复判文学质量；“演练接纳”是脚本自己的演练范围，不授权其他书。

本地实际产物位于 `.specwriter-experiments/v08-author-journey`（不入 Git）。打开其 exports/novel.html 可看正文，在该书运行 read 可用阅读器。没有调用付费 Qwen、实际 Microsoft GraphRAG 建库或新增 BGE 模型实验，本轮不更新此前模型表现结论。

## 仍未完成的验收

本次短篇只证明连接后的最小路径能执行，不满足优化方案第 17 节建议的 3–6 万字、三轮续写与独立质量评审。还没有通过自然语言让新用户完成全部作者旅程、干净环境安装、真实长篇远距离依赖和百万字验证。

B 阶段的卷/剧情段回顾和完结流程，C 的反馈修订与恢复贯通，D 的 GraphRAG 优化，以及 E 的规模验证依旧在路线中。认知匹配目前按登记主题做规则筛选，不是完整的“谁在何时通过什么得知”的语义推理；没有记录也不代表不知道。目标字数是创作指导，不是强制长度门槛。CLI 检查引用与声明记录，不能证明审阅者判断一定正确。
