# v0.11 历史核查、阶段回顾与完结验证

记录日期：2026-10-13（Asia/Shanghai）。本版将实际历史核查接入计划、当前章与独立审阅、旧章影响、阶段回顾和完结；资料准备与审阅完成分开，报告与作者确认完结分开。

## 功能与数据边界

- 原11个 Skills 接生命周期核查，新增 specwriter-recap/specwriter-finish，共13个。作者通常只用 `$specwriter`，Codex 按实际请求路由。
- memory check 管理请求、准备资料、逐题判断、不可变版本及 fresh/completed。CLI propose 自动登记并准备 plan，旧章另有 impact；查询失败保留 pending，不以准备过资料冒充核查完成。
- 当前工作包 review 绑定草稿/context，默认复用有效 context 与原 receipt；独立正式正文 review 不需要 work，读取所选有效范围并查询，不参与写作门禁或 context。新疑点可显式检索，新书空历史不调用 GraphRAG。
- plan 可进入目标章 context，review/impact 保持独立。impact 后文用于影响审计，不能成为目标章已发生事实、角色已知或写作授权。
- 核查保存后章审阅绑定 review-requirements 返回的 memoryCheckBindings，写入 review.memory_checks；结论版本更新后须实际重审，旧章审阅不能冒用新核查记录。
- recap/finish prepare 自动准备同ID历史任务，先实际完成其判断，再保存阶段审阅。报告精确引用正式版本，不从计划推断已发生剧情，不改 canon/Specs/指示或正式伏笔。
- finish accept 只记录真实作者当前版本完结指令。报告、正文、范围与相关输入变化使完成证明动态失效，历史保留；追加新章扩大范围后用新audit ID，不能改旧任务scope后复用证明。

## 独立 Skill 实际使用

另一代理只收到已安装 `$specwriter`、本书原始正式三章/Specs/计划与作者请求，自行执行“独立连续性审阅 → 阶段回顾 → 只检查当前全书是否可以完结”。作者允许余味性质的开放问题，明确不确认完结、不改正文/设定/授权，也不为纯审阅创建修订包；测试禁止联网和模型服务。

| 实际行为 | 结果与边界 |
| --- | --- |
| 无work的正式范围review | 保存recorded/fresh，completed=false；保留笔迹排除规则缺失的真实uncertain，没有假报通过或新建修订包 |
| recap同ID生命周期与阶段审计 | 历史核查completed/fresh；报告ready/fresh，保留1项warning，停航船线索deferred并说明下一段用途 |
| finish同ID生命周期与全书审计 | 历史核查已完成，但审计draft包含未收束的寻姐主线及needs-resolution；实际save被拒，未冒充ready |
| 作者完结接受 | 未执行accept，finish status=unfinished，完成receipt为0；允许余味没有被扩大为允许停止核心主线或确认完结 |
| 原作品与权限保留 | 三章、四份Specs与计划哈希相同，正式memory、contract、work/policy/instruction及Store generation不变，未创建新修订工作包 |
| 外部调用 | 三阶段各通过本地local后端准备，无网络、配置模型或付费服务调用 |

代理实际读完三章、采用约定、计划/章纲与正式记忆，为独立审阅保存正文引文和真实判断。它区分角色认知风险与已确定的世界矛盾，也区分开篇工作包完成与全书主线收束；本次没有修改作品来使检查通过。

结果位于该隔离书的 `skill-check-result.json`，可读报告为 `exercise/independent-audit-report.txt`。一次CLI误用裸memory命令后读取help并改为memory show，不是能力阻塞。这项行为检查证明这个有限请求能完成核查并保留实际问题，不证明所有Skill路由、文学判断或长篇质量。

## 核查结论的实际含义

prepared 是可读资料，不是已核查。save 要求逐题实际说明与有效正文证据，uncertain/conflicting 可以 recorded 但 completed=false；不能统一勾选通过来继续工作。独立审阅的问题报告不授予修订或接纳权限，工作包门禁只校验有关 plan/review/impact。

同任务且范围、问题与输入仍fresh时可复用prepared，Provider还可复用查询缓存；不同阶段/问题不保证命中。当前章review默认context-reuse，独立正式审阅及其他新非空阶段仍可能调用配置模型。额外检索只补来源缺口，不能声称所有阶段手工跳过了查询。

核查材料不采用assessment.accepted=false的原始GraphRAG回答，回到正式状态与原文。已发布回顾/完结报告不依赖可变draft读取，draft缺失或损坏单列draftError、历史报告仍可读，当前完结证明失效；这些故障边界的最终回归由整包检查记录。

历史引用绑定 chapter/revision/bodyHash 和逐字quote；当前草稿不能假造正式revision。阶段报告引用已接纳范围，机器hookInventory不改；未解决blocking/needs-resolution保留草案，unknowns或风格建议可保留。开放结局需要作者真实选择，不能自动强制全闭合或擅自替作者保留承诺。

## 尚未证明

核查目录仍整体解析；无关任务的不可变文件损坏可能阻止其他工作包推进，需要修复或从检查点恢复，不能新建工作包绕过门禁。version restore允许恢复正文与数据库一致、但带审计警告的快照，并返回warnings；恢复成功不能替代memory check/finish status对审计有效性的检查。

本轮尚未评估真实大量章节与核查任务下的目录扫描、freshness检查、内存或GraphRAG增量成本。

引用、版本与门禁只能检查记录和来源存在，不能证明语义蕴含、人物动机、读者体验或作者判断正确。本轮未使用付费模型做真实GraphRAG召回测评，未完成3–6万字、远距离依赖或百万字验证，也没有独立文学盲评。

完结证明不是“小说质量合格证”，不创建无人值守写作服务，不自动接纳草稿、授权续写或改正式伏笔状态。已有小说整本导入仍属于后续工作。
